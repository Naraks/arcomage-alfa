# Расширенный технический роадмап: Arcomage Roguelike

Этот документ предназначен для глубокого понимания структуры проекта и логики взаимодействия его частей. Идеально подходит для реализации с нуля в Godot 4.3+.

---

## 🏗 Архитектурные слои

В Godot важно разделять **Данные** (`Resource`), **Логику** (`Node`) и **Визуализацию** (`Scene`).

### 1. Слой данных (Resources)
Это "чертежи" объектов. Они не умеют ничего делать сами, но хранят параметры.

| Файл | Описание | Ключевые поля |
| :--- | :--- | :--- |
| `data/CardData.gd` | Шаблон карты | `name`, `cost`, `type` (ResourceType), `effects` (Array) |
| `data/PlayerData.gd` | Текущее состояние игрока | `tower_hp`, `wall_hp`, `bricks`, `gems`, `beasts`, `quarry`, `magic`, `dungeon` |
| `data/ArtifactData.gd` | Шаблон реликвии | `id`, `trigger` (Enum), `power` |

## 🚩 Milestone 1: "Сердце игры" (Ядро)

### 1.1 MatchManager (core/match_manager.gd)
Это "мозг" игры. Он управляет очередностью ходов и правилами.
*   **Тип узла:** Node (или Singleton).
*   **Логика:**
    1.  `setup_match()`: Создает два экземпляра `PlayerData` (игрок и ИИ).
    2.  `start_turn()`: Прибавляет ресурсы игроку (Ресурсы += Уровень Генератора).
    3.  `play_card(card, actor, target)`: Проверяет, хватает ли ресурсов -> Вычитает стоимость -> Применяет эффекты из `card.effects`.
    4.  `check_victory()`: После каждого хода проверяет, не достигло ли HP 0 или 100.

### 1.2 Система Эффектов
Вместо того чтобы писать код для каждой карты, мы создаем "интерпретатор" в `MatchManager`:
*   Если эффект `"damage"`, то `target.wall_hp -= value`.
*   Если эффект `"build"`, то `actor.tower_hp += value`.

## 🚩 Milestone 2: "Интерфейс и Визуал" (UI/UX)

### 2.1 Сцена Карты (entities/card/Card.tscn)
Это то, что игрок видит и на что нажимает.
*   **Структура:** `TextureRect` (фон) + `Label` (название) + `Label` (стоимость) + `Label` (описание).
*   **Скрипт:** При наведении мыши (сигнал `mouse_entered`) — увеличиваем масштаб через `Tween`. При клике — отправляем сигнал в `MatchManager`.

### 2.2 Боевой экран (ui/battle_screen.tscn)
*   **HUD:** Прогресс-бары для башен и стен.
*   **Hand:** `HBoxContainer`, который автоматически выравнивает карты в руке.

## 🚩 Milestone 3: "Противник" (ИИ)

### 3.1 AI Controller (entities/enemy/ai_controller.gd)
*   **Алгоритм для новичка (Весовая система):**
    1.  Берем все карты в руке ИИ.
    2.  Отсеиваем те, на которые нет ресурсов.
    3.  Каждой карте даем "очки приоритета":
        *   Мало HP у ИИ? Карты на защиту +10 очков.
        *   Мало HP у Игрока? Карты на урон +10 очков.
    4.  Выбираем карту с максимальным количеством очков.

## 💡 Советы для новичка

1.  **Сигналы (Signals):** Это основа Godot. Вместо того чтобы карта сама меняла здоровье башни, она должна сказать: "Меня нажали!". `MatchManager` услышит это и сам изменит данные.
2.  **Tween:** Используйте `create_tween()` для любых перемещений и плавных изменений цифр. Это делает игру "сочной".
3.  **Resources:** Никогда не пишите параметры карты (урон, цена) прямо в коде скрипта `card.gd`. Делайте это через файлы `.tres` в инспекторе. Это позволит вам создать 100 карт, не написав ни строчки нового кода.
