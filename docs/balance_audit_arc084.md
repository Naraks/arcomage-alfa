# ARC-084 — Аудит impact/cost по пулу карт

Источник: `dev_plan_tickets.md`, ARC-084, критерий приёмки №1 («Аудит текущего пула... задокументировано...
показана кривая роста impact/cost по возрастанию cost»). Этот файл закрывает именно этот пункт — только
аудит/цифры, **правки `cost`/`value`/новых карт в этом проходе нет** (критерии 2–4 ARC-084 — отдельная
работа поверх этого документа).

Источник данных — `data/cards/*.tres` напрямую (не `cards_list.md`), посчитано программно по всем 66 картам
(`docs/cards_list.md` остаётся источником истины по самим числам cost/value — здесь только производные
метрики поверх них, для дополнительной точности расхождений с `cards_list.md` не искал специально, но числа
совпадают с ним при выборочной сверке).

## 1. Методология

Три метрики — ровно то, что просит критерий приёмки: **impact / cost** по трём независимым осям, т.к. эффект
карты обычно принадлежит только одной из них (комбо-карты дают значения сразу в двух):

- **R_dmg** = (`damage` + `direct_damage` + `reduce_wall` по врагу) / `cost`. `reduce_wall` (снятие стены
  врага без урона по башне) посчитан на той же оси, что и урон — механически это то же самое «убрать HP
  у оппонента», только без возможного перелива в башню.
- **R_стена/башня** = (`build_wall` + `build_tower`, только `target: self`) / `cost`.
- **R_ген** = (`mod_quarry` + `mod_magic` + `mod_dungeon`, только `target: self`) / `cost`. Это **разовая**
  метрика (прирост генератора за одно применение карты), не пожизненная ценность — см. оговорку в разделе 4.

**Не попадает ни в одну из трёх осей** (9 карт, см. раздел 3): `draw_card`, `steal_resource`,
`drain_resource`, порча генератора врага (`mod_*` с `target: enemy`). Эти эффекты меряются в разных единицах
(карты, чужие ресурсы, чужой генератор) — сминать их в одно число с уроном/стеной было бы фиктивной
точностью, поэтому они просто перечислены отдельно, без ratio.

**Условные эффекты** (`Ремонт`, `Резервы` — «если стена < N, то X, иначе Y»): взята ветка `then` (бóльший
эффект, срабатывающий когда стена реально просела) как показательное значение, а не средневзвешенное — это
эвристика, не точный расчёт мат. ожидания за партию.

**Не учтено намеренно** (см. раздел 5 «Ограничения»): `direct_damage` по номиналу не отличается от `damage`
той же величины, хотя `direct_damage` объективно сильнее (не режется стеной) — комбо-карты на `direct_damage`
(Дракон, Виверна, Метеорит, Армагеддон, Древний левиафан) в реальности чуть недооценены этой таблицей.

**Вывод: кривая не растущая ни на одной из трёх осей.** Это именно то, что описание тикета формулирует

воздействия») — здесь это подтверждено числами:

- **R_dmg** колеблется вокруг ~2.0 на всём диапазоне 1–8 (провал на cost=2, пик на cost=6). Пик на cost=6
  целиком объясняется двумя картами (Гидра 3.17, Дракон 2.83 — обе комбо: урон + `reduce_wall`), не общим
  трендом; на cost=8 показатель падает обратно к ~2.0, т.е. три самые дорогие карты в игре не сильнее по
  эффективности, чем `Таран` за 1.
- **R_стена/башня** не просто плоская, а **снижается**: у cost=1 показатель (2.43) выше, чем у любого
  cost 2–5. Дороже вложенная в стену/башню карта — тем **хуже** отдача на единицу cost, ровно обратный
  эффект от желаемого.
- **R_ген** тоже монотонно падает от 1.50 (cost=1) до 0.83 (cost=6) и полностью отсутствует на cost 7–8 —
  ни одной карты-генератора дороже cost=6 в игре нет вообще.

## 4. Экономические карты — отдельная оговорка про «разовость» метрики

R_ген считает **разовый** прирост генератора за cost, но реальная ценность генератора — это
`value × (сколько ходов ещё останется в партии)`, т.к. прирост действует на все последующие ходы, а не
разово. Это значит R_ген **занижает** реальную силу дорогих генераторов относительно дешёвых, если
дорогая карта разыгрывается позже (меньше оставшихся ходов), и наоборот. У симулятора (ARC-054) нет
задокументированной метрики «среднее число ходов на партию» — без неё нельзя честно посчитать «пожизненную»
ценность, поэтому здесь она не считается, только называется как открытый вопрос для калибровки в критерии 4
ARC-084 (повторный прогон `battle_simulator.gd`).

Уже известный факт из ARC-023 (winrate-отчёт симулятора) держится в силе и без этой калибровки: **все
«чистые» генераторные карты (без немедленного боевого эффекта) кластеризуются в 35–47% winrate независимо
от cost-тира**, тогда как боевые/стеновые карты — в 50–84%. Т.е. проблема не только в том, что R_ген не
растёт с cost (раздел 3) — весь генераторный архетип целиком слабее остальных, на любом cost.

## 6. Приток ресурсов быстрее оттока — количественная иллюстрация

Описание тикета: «в руке (5 карт максимум) почти всегда лежат только дешёвые варианты». Грубая
комбинаторная оценка (не симуляция игры, просто гипергеометрическое распределение — раздача 5 карт без
возврата из полного 66-карточного пула, без учёта колод отдельных ИИ-профилей/игрока, порядка ходов,
сброса и т.д., см. ограничения в разделе 7):

| | Cost ≥ 5 (14 карт) | Cost ≥ 7 (4 карты) |
| :--- | ---: | ---: |
| Матожидание карт такой цены в руке из 5 | 1.06 | 0.30 |
| P(в руке НЕТ ни одной такой карты) | 29.1% | 72.4% |

Т.е. даже без учёта реальной колоды и порядка розыгрыша — почти три хода из четырёх в руке физически не
будет ни одной карты cost 7–8, на которую можно потратить накопленный запас. Это количественно подтверждает
интуицию из описания тикета: дефицит дорогих карт-«стоков» — не только про их слабую эффективность
(разделы 3–4), но и про их banal редкость в пуле (раздел 2).

## 7. Ограничения методологии

- `direct_damage` не отделён от `damage` по номиналу (см. раздел 1) — недооценивает карты на прямом уроне
  по башне.
- R_ген — разовая, не пожизненная метрика (раздел 4); нет данных о среднем числе ходов партии, чтобы
  посчитать альтернативную «пожизненную» версию.
- Условные эффекты (`Ремонт`/`Резервы`) взяты по ветке `then`, не по мат. ожиданию за партию.
- Веса приоритета в AI-стратегиях (`calculate_card_priority()`) не учтены вовсе — эта таблица чисто про
  данные карт, не про то, насколько ИИ (и тем более игрок) реально разыгрывает каждую карту. Реальный
  winrate/usage rate — только через повторный прогон `battle_simulator.gd` (критерий 4 ARC-084), не через
  этот документ.
- Раздел 6 — комбинаторная иллюстрация на полном 66-карточном пуле (как видит его симулятор для стороны
  ИИ, см. ARC-054), не учитывает реальную колоду игрока (набирается по ходу забега, ARC-015) или колоду
  конкретного ИИ-соперника.
- Влияние артефактов (Эпик E, например бонусы к генераторам/лимиту руки) не учтено — таблица про сырые
  данные карт вне контекста конкретного забега.

## 9. Направления для критериев 2–4 (не реализовано в этом проходе)

Только наблюдения из данных выше, без изменения `cost`/`value` — решение, что именно менять, ARC-084
оставляет на отдельный проход:

- **Критерий 2** (карты-«бомбы» 9+, либо непропорциональный impact у существующих 5+): раздел 3 показывает,
  что нужен рост R_dmg/R_стена/R_ген именно на хвосте (cost 6–8+), а не общее повышение чисел — сейчас
  хвост **хуже** середины по двум осям из трёх.
- **Критерий 3** (скорость притока ресурсов): раздел 4 напоминает, что генераторные карты и без правки
  cost/value уже проигрывают боевым по winrate (ARC-023) — снижение базового притока без одновременного
  усиления генераторных карт рискует сделать архетип ещё менее играбельным, а не просто продлить партию.
- Раздел 6 — прямой довод в пользу критерия 2: даже при полностью исправленной эффективности дорогих карт,
  если их всего 4 из 66, они физически редко оказываются в руке. Увеличение количества карт cost 7+
  (не только их силы) — отдельный лёгкий рычаг, не требующий трогать существующие 62 карты вовсе.
