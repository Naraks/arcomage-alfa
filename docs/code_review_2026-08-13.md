# Код-ревью кодовой базы (2026-08-13)

Ревью выполнено агентом по `core/`, `entities/`, `data/`, `ui/`, `tests/`, `tools/` и конфигурации проекта
(`project.godot`, CI, `.gdlintrc`, `.pre-commit-config.yaml`). Код не менялся — документ фиксирует
замечания и предложения на будущее.

## Баги и риски

### core/

- `core/match_manager.gd:201-202` — `_build_generic_card_pool()`: если ни одна карта из
  `STARTER_DECK_CARD_PATHS` не загрузится, `pool` останется пустым, и `pool.pick_random()` в цикле
  `while pool.size() < 20` рухнет на пустом массиве.
- `core/match_manager.gd:287-294` — таймер ИИ-хода не привязан к «сессии» матча: если между стартом
  таймера и его срабатыванием матч пересоздаётся (`setup_match()`), колбэк отработает поверх нового
  матча — нет отмены таймера при рестарте.
- `entities/card/card.gd:38-45` — `_gui_input` обращается к `card_data.card_name` без null-проверки,
  хотя в соседнем `_on_mouse_entered` (строка 74) такая проверка есть.
- `core/profile_manager.gd:201-221` — ошибки записи (`FileAccess.open` → `null`) и ошибки парсинга JSON
  при загрузке профиля проглатываются без единого лога — при повреждённом сохранении игрок тихо теряет
  прогресс без объяснения.
- Ни в `ProfileManager`, ни в `RunSaveData` нет поля версии сохранения — при будущем изменении структуры
  не на чем строить миграцию/обратную совместимость.
- `_apply_effect` (`match_manager.gd`), `apply_artifact_effect` (`artifact_manager.gd`) и `_score_effect`
  во всех AI-стратегиях разбирают эффекты по строковому полю `"type"` без ветки `_`/валидации — опечатка
  в `.tres` карты тихо гасит эффект без предупреждения.
- `core/match_manager.gd:537` — `apply_damage` не проверяет `amount` на неотрицательность; отрицательное
  значение в данных карты тихо «лечит» вместо урона.

### ui/

- `ui/event/event_screen.gd:17-18` — `load(_pick_random_event_path())` не проверяется на `null` перед
  использованием в `_build_ui()`.
- `ui/reward/reward_screen.gd:56-90` — слоты наград индексируют массив карт без проверки размера
  относительно числа слотов — потенциальный `Array index out of bounds`, если каталог карт окажется
  урезан.
- `ui/battle/battle_screen.gd:347-372` — во время 0.3с анимации клика по карте блокируется только сама
  нажатая карта, но не весь `hand_container` — можно успеть кликнуть вторую карту и запустить
  параллельный `play_card_by_index`.
- `ui/shop/shop_screen.gd:14` — `_transaction_in_progress` не защищает ни от чего: код синхронный,
  гонка физически невозможна, флаг просто вводит в заблуждение при чтении.
- `ui/deck/deck_screen.gd:69-75` — `_load_deck_to_show()` выглядит как геттер, но имеет побочный эффект
  (перезаписывает `MatchSettings.*` через `RunSaveManager.load_run()`), вызывается безусловно даже когда
  экран встроен в профиль.
- Несогласованная защита `get_viewport_rect()` вне дерева сцены: в `settings_screen.gd` есть fallback, в
  `event_screen.gd`/`rest_screen.gd` — нет (пока не стреляет, т.к. эти экраны не тестируются через прямой
  вызов `_build_ui()` вне дерева, но это мина для следующего теста по аналогии).

## Дублирование / архитектура

- 4 AI-стратегии (`aggressive/builder/default/economist`) почти дословно повторяют цикл выбора лучшей
  карты — стоит поднять в базовый класс как шаблонный метод, оставив подклассам только `_score_effect`.
- ~~«Золотой» акцентный цвет задан 6 разными близкими hex-значениями в разных экранах вместо общей
  темы.~~ **Исправлено.** Цвет вынесен в `ui/theme/ui_colors.gd` (`UIColors.GOLD`/`GOLD_HOVER`/
  `GOLD_PRESSED`), 7 экранов (`main_menu`, `event`, `meta_shop`, `profile`, `rest`, `settings`, `shop`)
  теперь ссылаются на общую константу вместо своих hex-литералов. `ui/theme/base_theme.tres` как
  отдельный вопрос (тема проекта по-прежнему не переиспользуется явно из кода экранов) не тронут —
  это выходило за рамки конкретной жалобы на дублирование цвета.

## Стиль / типизация

- В `ui/`: хардкод русскоязычных строк интерфейса без вынесения в константы (не критично для
  моно-язычного проекта, но масштабный рефакторинг при будущей локализации); магические числа
  позиционирования без имён; только `main_menu.gd` защищён от повторного вызова `_build_ui()`, остальные
  14 экранов — нет.

## Производительность

- `entities/card/curved_label.gd:_draw()` — при анимации «плавания» текста каждый кадр пересчитывает
  `placements`/`jitter` заново, хотя они зависят только от текста/seed, а не от времени — стоит
  кэшировать.
- `core/audio_manager.gd:play_sfx()` создаёт новый `AudioStreamPlayer`-ноду на каждый звук (в т.ч. частый
  hover-звук карт) вместо пула плееров.
